# szfo-monitor — важные кадровые квоты, выпуск от 23.11.2026

## Область изменений

**Меняется только второй поток новостей** (`news_monitor.py` и `.github/workflows/news.yml`).
**Не меняются** `generate.py`, основной workflow указов, `notify_telegram.py`,
`news_relevance.py`, уже сохранённые события, Telegram Secrets и расписание
«каждые 3 часа».

Новая категория `workforce` («Персонал» 👥) — подтверждённое создание от
100 рабочих мест, увеличение штата или одобренные квоты на привлечение
работников к площадке в СЗФО. Согласованная квота **не равна** фактическому
числу принятых работников. Вакансии, отказанные заявки и неподтверждённые
планы не учитываются.

его сайта/ленты из GitHub Actions заранее не подтверждена.

## Контроль ИМЕННО 23 ноября 2026 г.

Дополнительный файл `featured_staffing_2026-11-23.json` содержит проверенную
публикацию «Росбалта» с оригинальными URL и датой 23.11.2026. Он нужен как
**одноразовый резервный источник**, если парсер сайта не извлечёт статью.
Этот материал не вставляется напрямую в `events.json`: он проходит общие
`detect_all`, определение региона, фильтр и дедупликацию. Он активен
**только 23.11.2026 по Москве**, далее никогда не импортируется.

Оригинал:
https://www.rosbalt.ru/news/2026-11-23/zabrali-82-vseh-kvot-v-2027-godu-v-lenoblast-priedut-18-6-tys-rabochih-iz-kitaya-5739313

После загрузки файлов необходимо **23 ноября по московскому времени** запустить
**Actions → «Новости — назначения и звания» → Run workflow → main**.
Обязательно проверить в логах шаги:

1. `Тесты значимого расширения персонала` — `OK`;
2. `Тесты публикации Росбалта и дедупликации` — `OK`;
3. `Подключить Росбалт ко второму потоку` — источник добавлен или уже есть;
4. `Сбор новостей и поиск событий` — среди кандидатов статья «Росбалта»;
5. `Проверить публикацию Росбалта от 23 ноября` — строка `PASS: статья Росбалта опубликована в events.json`;
6. `Коммит и push изменений` — статус success;
7. `Уведомление в Telegram о новых событиях` — отправка при наличии новых событий.

Шаг №5 **завершает workflow ошибкой**, если конкретной статьи нет в
`data/news/events.json` с типом `workforce`, датой 2026-11-23 и регионом
«Ленинградская область». Это не позволяет принять незаметную потерю новости.
В `news.html` появится строка с типом **«Персонал»** и исходной ссылкой.
В **первом** прогоне (если событие ранее не сохранено) `run_summary_news.json`
должен содержать его в массиве `new`, после чего штатная логика отправит
уведомление. На **повторном** прогоне повторная рассылка не нужна.

> Внимание: загрузка файлов сама по себе не запускает workflow. Нельзя
> гарантировать фактическую доставку в Telegram или публикацию GitHub Pages
> без просмотра успешного прогона GitHub и Telegram-лога. После полуночи
> 24 ноября по Москве резервная публикация не импортируется автоматически.
