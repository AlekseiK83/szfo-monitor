Загрузить в репозиторий только:
  news_monitor.py                  → корень репозитория (заменить)
  news_relevance.py                → корень репозитория (заменить)
  tests/test_news_relevance.py     → папка tests/ (заменить)

  .github/workflows/news.yml (расписание второго потока)
  Telegram, Secrets, notify_telegram.py, news_sources.json

Что исправлено:
- Благоустройство малых территорий, скверов и площадок не считается
  значимым сопутствующим инфоповодом, даже если об этом пишет губернатор.
- Точное исключение: пост об открытии территории у Колхозного рынка.
- Новости о реальных назначениях, увольнениях и званиях не отклоняются
  только из-за слова «благоустройство» в названии учреждения.
- Отклонённые новости фиксируются в diagnostics/rejection_reasons
  в run_summary_news.json, когда детектор распознал их как событие.
- Ранее сохранённые события перепроверяются процедурой reconcile().

Порядок действий:
1. Распаковать архив и загрузить три файла по указанным путям.
2. Сделать Commit changes на GitHub.
3. Запустить GitHub Actions → «Новости — назначения и звания».
4. Проверить summary в run_summary_news.json и публикацию news.html.

Прежняя логика: если новых событий нет, Telegram ничего не отправляет.
Отдельная контрольная рассылка не добавлялась.

Локальные тесты: python -m unittest discover -s tests -p 'test_news_relevance.py' -v
Результаты прогона по реальным лентам в архив не включены.
