# 🏛 Мониторинг наградных указов СЗФО

Ежедневный автоматический дайджест награждённых государственными наградами из **10 регионов Северо-Западного федерального округа**. Данные — с официального портала <http://publication.pravo.gov.ru>.

## Как это работает

- **GitHub Actions** каждый час (в 7 минут часа, круглые сутки) проверяет, обработан ли вчерашний день по Москве. GitHub часто откладывает или пропускает запуски по расписанию, поэтому вечерний запуск (после 19:00 МСК) дожидается 00:12 и сразу обрабатывает закончившийся день. Первая попытка, для которой есть работа, скачивает наградные указы за вчера, распознаёт PDF через Tesseract OCR, извлекает награждённых из регионов СЗФО и коммитит готовый HTML в репозиторий.
- **GitHub Pages** раздаёт готовые HTML-файлы по публичному URL.
- **Пользователи** просто открывают ссылку в браузере и мгновенно видят свежий дайджест и архив за все дни.

## Развёртывание (10 минут, один раз)

Нужен только бесплатный аккаунт на GitHub (email + пароль, никаких карт).

### Шаг 1. Регистрация

<https://github.com/signup> → email → пароль → username.

### Шаг 2. Создание репозитория

1. <https://github.com/new>
2. **Repository name:** `szfo-monitor` (или любое)
3. **Public** ← обязательно, иначе GitHub Actions на public-репо будет ограничен
4. **Add a README file** — снимите галку, README у нас свой
5. **Create repository**

### Шаг 3. Загрузка файлов

На странице свежего репозитория нажмите **uploading an existing file** (ссылка в тексте) или **Add file → Upload files**.

Перетащите **все 4 файла из этого комплекта** сразу:

- `generate.py`
- `requirements.txt`
- `.gitignore`
- `.github/workflows/generate.yml` ← папка `.github/workflows/` создастся автоматически, если сохранить структуру при перетаскивании

Внизу поле «Commit changes» → **Commit changes**.

> **Важно про `.github/workflows/generate.yml`:** файл должен лежать именно в папке `.github/workflows/`. Если веб-интерфейс GitHub при перетаскивании сплющил структуру — создайте папку вручную: **Add file → Create new file**, введите путь `.github/workflows/generate.yml`, вставьте содержимое, коммит.

### Шаг 4. Включение GitHub Pages

1. **Settings** (в шапке репо)
2. Слева в меню **Pages**
3. **Source: Deploy from a branch**
4. **Branch: main** / **Folder: `/ (root)`**
5. **Save**

Через 1-2 минуты вверху появится плашка с URL: `https://ВАШ-USERNAME.github.io/szfo-monitor/` — это будущий адрес дайджеста.

### Шаг 5. Первый запуск workflow

Автоматически он запустится в ближайшие 7 минут нового часа. Чтобы получить первый отчёт сразу:

1. Вкладка **Actions** (в шапке репо)
2. Слева выберите **Ежедневный дайджест СЗФО**
3. Справа кнопка **Run workflow** → **Run workflow**
4. Дождитесь окончания (5–10 минут, прогресс виден в реальном времени)

По завершении в репозитории появятся файлы:
- `index.html` — главная страница
- `reports/YYYY-MM-DD.html` — отчёт за день
- `reports/YYYY-MM-DD.json` — сырые данные
- `reports/index.json` — список дат

Через минуту после коммита GitHub Pages обновится, и по URL из шага 4 будет виден дайджест.

### Шаг 6. Раздача ссылки

Ваш публичный URL: **`https://ВАШ-USERNAME.github.io/szfo-monitor/`**

Этой ссылкой можно делиться с любым количеством пользователей — регистрация не нужна, они просто открывают её в браузере. Дайджест обновляется автоматически каждый день.

## Запрос за конкретную дату (для админа)

Если нужен отчёт за произвольную дату (не за вчера):

1. **Actions** → **Ежедневный дайджест СЗФО** → **Run workflow**
2. В поле «Дата в формате YYYY-MM-DD» укажите нужную (например, `2026-08-12`)
3. **Run workflow**
4. Через 5–10 минут отчёт появится в списке на главной странице

## Настройка расписания

Файл `.github/workflows/generate.yml`, строка `cron: '7 * * * *'` — запуск в 7 минут каждого часа круглые сутки. GitHub иногда пропускает запуски по расписанию, поэтому попыток несколько: первая обрабатывает данные, остальные сразу завершаются. Не ставьте минуту `0`: в начале часа GitHub сильнее всего задерживает запуски. Формат стандартный cron. Например:
- `'0 5 * * *'` — 5:00 UTC (8:00 МСК)
- `'0 3 * * 1-5'` — 3:00 UTC только по будням

Изменение через веб-интерфейс: откройте файл в GitHub → карандаш (Edit) → правьте → **Commit changes**.

## Лимиты

- **GitHub Actions:** для публичных репозиториев — **безлимитно** (для приватных было бы 2000 минут/месяц).
- **GitHub Pages:** soft-limit 100 ГБ трафика в месяц, 10 сборок в час — на несколько сотен пользователей в день с запасом.
- **История:** копится в репозитории, размер файлов небольшой (десятки КБ на день) — на годы хватит.

## Диагностика

- **Workflow упал?** Actions → выберите неуспешный запуск → раскройте шаги, увидите лог. Чаще всего — временная недоступность API pravo.gov.ru; следующий запуск отработает.
- **Страница не открывается?** Settings → Pages: убедитесь, что источник — main / root, статус — «Your site is live at…».
- **За дату 0 наградных указов?** Это нормально: не каждый день Президент подписывает наградные указы. Пустая запись всё равно попадёт в архив.

## Что делает скрипт (кратко)

1. `GET /api/Documents?block=president&Date=…` — список указов Президента за день
2. Фильтр по `complexName`: о награждении / присвоении звания / объявлении благодарности / поощрении
3. `GET /file/pdf?eoNumber=…` — скачивание PDF
4. `pdfplumber` для текстового слоя, при неудаче — `pdf2image` (250 DPI) + `pytesseract` с русской моделью
5. Парсер награждённых: три типа заголовков наград, splitter-маркеры, склейка OCR-переносов, обрезка position_org
6. Матчер регионов СЗФО во всех падежных формах
7. Генерация HTML отчёта за день + обновление главной страницы со списком

## Второй поток: назначения и звания по новостям

Кроме указов, монитор читает новостные ленты регионов (`news_sources.json`: сайты правительств и заксобраний, региональные СМИ, ведомства — МВД, СК, прокуратура, МЧС, Росгвардия, ФСИН, публичные Telegram-каналы) и выбирает два типа событий:

1. **Звание** — региональные звания («Почётный гражданин …», «Заслуженный … области»), генеральские и специальные звания руководителям ведомств.
2. **Назначение / отставка** — руководитель или заместитель в правительстве региона, подведомственном учреждении, крупнейшей компании (список в `news_sources.json → organizations`) или силовом ведомстве.

Результат — страница `news.html` (ссылка с главной) и сообщение в тот же Telegram-канал.

- **Workflow «Новости — назначения и звания»** (`news.yml`) запускается каждые 3 часа: `python news_monitor.py` собирает ленты, события пишет в `data/news/events.json`, страницу — в `news.html`, новые события отправляет в Telegram (`--notify`).
- **Workflow «Проверка источников новостей»** (`news-check.yml`, запуск вручную) печатает таблицу: какие источники доступны из GitHub Actions, где нашлась RSS-лента, где читаются заголовки со страницы. Запустите его первым после загрузки файлов и уберите из `news_sources.json` источники с `error`, либо замените их Telegram-каналом (`"type": "telegram"`).
- Для сайтов адрес RSS задавать не нужно: скрипт сам находит ленту по ссылке в шапке сайта (`<link rel="alternate">`) и запоминает её в `data/news/feeds.json`; если ленты нет, читает заголовки со страницы `news_url`.
- Дедупликация — по типу события и фамилии (`data/news/seen.json`, 45 дней): одно назначение из пяти источников даёт одно событие.

### База знаний: какие инфоповоды ловим

| Тип | Что считаем событием | Для кого |
| --- | --- | --- |
| Назначение / отставка | назначен, возглавил, избран, утверждён, врио, и.о.; покинул пост, освобождён от должности | руководители и заместители: правительство региона, избирком, уполномоченные, Общественная палата, главный федеральный инспектор, силовые ведомства, Северный и Балтийский флоты, областные учреждения, крупнейшие компании, отделения Банка России и Сбербанка |
| Звание | «Почётный гражданин», «Заслуженный … области», генеральские и адмиральские звания | все лица региона |
| Утрата | скончался, ушёл из жизни | руководители учреждений и компаний, почётные граждане |
| Визит | Президент, премьер, полпред, спикеры палат, федеральные министры, главы госкорпораций посетили предприятие или открыли объект | ключевые компании и учреждения |
| Юбилей | круглая дата организации (25, 30, 40, 50 … лет) | организации из базы знаний; юбилеи людей не считаем |
| Запуск | спуск на воду, ввод в эксплуатацию, первый камень, старт производства, крупный контракт | компании и учреждения из базы, стройки на млрд, заводы, энергоблоки, больницы |
| Награда | орден, медаль, знак отличия, премия Правительства организации или её руководителю | организации из базы знаний |
| Статус | вошёл в топ, системообразующее предприятие, победа во всероссийском конкурсе, федеральный статус | организации из базы и областные учреждения |
| Собственность | смена владельца, банкротство, изъятие в доход государства, задержание руководителя | только компании из базы знаний |

Не ловим: начальников отделов, районные больницы и поликлиники, школы, дома культуры, партийные должности, спортивные клубы, муниципальный уровень (кроме глав региональных столиц), планы и слухи («может возглавить», «кандидаты»).

База знаний — раздел `organizations` в `news_sources.json`: по 40–120 ключевых компаний и учреждений на регион (заводы, порты, АЭС, флоты, вузы, областные больницы, театры, музеи). Название ловится в любом падеже; аббревиатуры (ОСК, БФУ) — только целиком. Добавить организацию — одна строка в JSON, код менять не нужно.
